## 6.12.1 的醫囑解析與檢閱等待

2026-10-15，以同一 Python 3.11.3 環境交錯執行 `2ab18b4` 與更新後的解析器，各五次解析相同的 500 筆合成醫囑。每筆都有獨立案例號、醫囑及報告連結，兩版的 500 筆 typed 結果完全一致；純解析耗時中位數分別為 416.37 ms、220.53 ms，減少約 47%。不含院內登入、網路、資料庫或附件下載，不能換算成實際病人的整體抓取加速倍率。完整量測存於本機 `.build/order-index-benchmark.json`，沒有真實病歷。

結構性回歸另核對普通醫囑不進入 PDF／PACS 解析，跳脫字串仍走完整附件及身分驗證；歷史讀取共用 WAL 快照，類別結果分別保存與發布，成功類別不因其他類別失敗而重抓。前端合併重疊輪詢，依資料保存時間、完整性與問題清單決定是否重畫，避免反覆重啟載入動畫、清除輸入或重新載入附件；浮動進度的內容未改變時保留原節點。

## 6.9.0 的刀表同步驗證

未變動、事件綁定完整的刀表，在合成 10 人／1 個月、50 人／12 個月及 200 人／24 個月案例均只完成兩輪完整識別掃描，沒有回寫。舊監控逐人重新讀取，50 人案例需 52 輪；本版只在缺少事件綁定時分批重新定位與回寫，刪除前仍涵蓋月份、FU、All 及封存識別。

掃描輪數不等於 HTTP 請求數：每輪仍依月份大小切分範圍。本版將多個分頁的有限範圍合併讀取，只取得監控所需的值、識別、註記及刪除線；管理／封存仍使用完整原生格式讀取。

2026-10-13 以正式刀表 195 筆排程核對，單輪完整格式讀取使用 14 個 Sheets 請求，監控讀取使用 5 個；兩者的識別、區塊、日期／院區、問題清單及預期事件內容一致。線上只建立並回收一個合成批次 metadata，最後確認已不存在，沒有修改臨床儲存格或日曆事件。這是當時刀表的請求量，月份及列數改變時會不同。

合成測試另連續執行 650 個完成批次，確認暫時 metadata 不累積，並涵蓋清理失敗、清理後中斷、結果不明批次保留及封存兩階段續接；完成證據保存於本機 SQLite。

## 6.6.42／SDK 0.22.2 的合成量測

2026-10-04，在本機暫存 SQLite 與合成 SDK 上驗證；沒有讀取真實病歷或連接院內服務。以下為索引建立後，三次暖機讀取的中位數。SQL 計數包含交易與 PRAGMA，耗時包含計數工具的額外成本，不含回應 JSON 序列化。

| 合成病歷數 | 單一任務 40 筆分頁 | 全資料庫 40 筆分頁 | 1,000 人進度摘要 | 無符合病人的快取清單 | 精簡狀態 |
|---:|---:|---:|---:|---:|---:|
| 1,000 | 16.6 ms | 18.9 ms | 9.2 ms | 6.5 ms | 5.8 ms |
| 5,000 | 29.8 ms | 71.8 ms | 6.7 ms | 7.7 ms | 11.5 ms |
| 20,000 | 51.1 ms | 243.9 ms | 5.9 ms | 7.3 ms | 8.1 ms |

- 所有 40 筆分頁都只解析 40 份病歷全文，約 0.33 MiB；資料庫增至 20,000 筆時解析量不增加。前次檢視的 5,000 筆任務搜尋單次約 1.5 秒、解析 42.6 MB，這次樣本內容並非逐筆相同，因此不以兩者推算精確加速倍率。
- 進度摘要使用 4 個 SQL 敘述，解析約 708 bytes 的任務狀態，回應約 502 bytes；不解析 SOAP 或固定病人名單。動態進度更新不改寫完整任務文件。
- 白內障 65 人 × 10 醫囑的狀態查詢使用 13 個 SQL 敘述，三次中位數約 120.4 ms；回應約 17.5 KiB，不解析 SOAP。原檢視樣本使用 3,259 個 SQL 敘述，已達成 100 個以內的驗收門檻。
- 快取清單不在 Python 解析病歷或數值文件，SQL 內完成分類統計與病人分頁。清除預覽保留選取範圍與共用附件引用的指紋檢查。

首次建立 1,000／5,000／20,000 筆搜尋索引分別約 0.23／1.92／8.70 秒。索引以病歷內容摘要、資料異動標記及 TAG 規則版本維護；每批 200 筆提交，可在中斷後接續。這項成本發生於尚未建立索引或規則變更時。

重現方式：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\benchmark_efficiency.py
```

完整計數輸出至 `.build/efficiency-benchmark.json`。結構性驗收另由 `tests/test_architecture_efficiency.py` 及 `tests/efficiency_ui.js` 檢查：任務範圍與 TAG 計數、當頁全文解析、摘要計數與固定文件、附件遺失、分類分頁、4／64 排程與重複請求、跨帳號隔離、WAL 讀寫並行、結構更新回復、共用狀態、隱藏頁面及終態記憶體釋放。

既有 API 未指定摘要或分頁參數時仍回傳原有完整內容。介面使用 `summary=1` 及每頁 40 筆；可選分頁上限 200 筆。以上耗時是當時 6.6.42／SDK 0.22.2 的量測，不代表目前版本重新測得的耗時。
