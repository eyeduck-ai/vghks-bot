# 操作說明

Windows 單檔 EXE，本機瀏覽器介面。系統入口：**門診、審查查詢、薪資業績查詢、手術**。

## 開始使用

1. 執行下載的 `VGHKS-bot.exe`。更新既有程式時，先關閉舊程式，再以新版 EXE 取代，讓 EXE 與原有 `VGHKS-bot-data` 資料夾保持同層，即可沿用資料。首次使用才建立空白資料庫並輸入院內帳密；成功後預設保存，下次驗證上次帳號。
2. 從「選擇病人清單」勾選病人，再開啟對應工具；也可在清單或進階工具輸入多個病歷號／身分證號。空白或 Enter 會立即核對一筆，貼上多筆會逐位加入。選擇病人清單以表格勾選或取消；進階工具仍可點選已選病人的 badge 移除。各工具也能套用已保存集合。
3. 審查查詢系統：按「立即同步」取得此帳號醫師的完整清單，再以本機篩選檢閱。全部案件在同一頁，以表格捲動檢閱，不分頁。
4. 薪資業績查詢：設定薪資登入資訊 →「立即更新」保存目前公布期別 → 檢閱或匯出報表。
5. 手術系統：即時刀房可開啟院內看板；手術排程預設查詢登入帳號，也可輸入其他醫師卡號。日期預設今天至兩個月後，可自行修改。
6. 「資料庫管理」可從登入頁或左側開啟，不必先連上院內。

病歷檢閱頁的「收合病人清單」可讓 SOAP 使用更寬的顯示區域，需要切換病人時可再展開。左側功能列固定顯示。

本版使用資料格式 1，不讀取或轉換格式 1 之前的資料庫與 DPAPI 憑證。原有檔案不會自動刪除；首次使用空白資料庫需設定帳號與 Google 金鑰。

## 資料庫管理

| 操作 | 行為 |
| --- | --- |
| 建立新資料庫 | 建立空白、獨立的資料庫；名稱可自訂，路徑留白使用預設資料目錄 |
| 開啟資料夾 | 指定含 `database.json` 的資料夾，選擇一般使用或唯讀檢閱 |
| 唯讀檢閱 | 在暫存副本查看已保存內容，禁止登入、抓取及修改，不改動來源 |
| 建立備份 | 保存帳號、憑證、病歷、審查、任務、設定及附件；備份固定以唯讀開啟 |
| 建立可編輯副本 | 從目前資料庫或備份建立另一份，可開啟後繼續工作 |
| 匯入為獨立資料庫 | 先預覽帳號／病歷／審查／附件數量，再複製至本機；不合併內容、不改動來源 |
| 重新命名 | 修改顯示名稱，資料夾位置不變 |
| 移出清單 | 移除管理清單的捷徑，原始資料夾保留 |

切換、複製、備份前請暫停所有帳號任務，並等目前查詢完成。目的資料夾必須不存在，不覆寫既有資料。資料庫切換後重新載入頁面，避免舊頁面寫入新資料庫。

EXE 版本與資料格式分開管理；本版資料格式為 **1**。開啟／匯入會檢查格式與 SQLite 完整性，不支援的格式直接拒絕，不自動升級。如果上次的資料庫已移走或格式不符，仍可進入資料庫管理，選擇其他資料庫。要查看目前格式的歷史狀態，開啟該備份；要繼續修改，先建立可編輯副本。未來若資料格式改變，需使用支援該格式的 EXE；本版不提供跨格式轉換。

## 隨身碟與儲存位置

預設資料位於 **EXE 同層的 `VGHKS-bot-data`**：

```text
VGHKS-bot.exe
VGHKS-bot-data/
  databases.json                         資料庫清單及上次開啟位置
  datasets/<資料庫目錄>/
    database.json                        名稱、識別碼、資料格式
    accounts.sqlite3                     帳號、可攜式密碼與偏好
    accounts/<帳號代碼>/
      clinical.sqlite3                   病歷、審查追蹤、薪資報表、集合、任務與可攜式憑證
      diagnostics/<工作階段代碼>/         SDK 請求診斷 JSONL 與結束摘要
      assets/<SHA-256>                    PDF／影像
      runs/                              抓取任務日誌
      settings.json                      tag 與請求設定
  backups/<備份目錄>/                     完整資料庫備份
```

使用側欄「結束程式」後，攜帶 **EXE + 整個 `VGHKS-bot-data`** 即可換電腦使用，不需重輸密碼或重新匯入 Google 金鑰。資料庫中的憑證與解密資料一同保存，不綁定 Windows 使用者；持有整份資料的人能使用這些憑證。密碼與私鑰不回傳瀏覽器或寫入任務日誌。

「開啟資料夾」可以指向外部位置；外部資料不會跟著預設目錄移動。若要一起攜帶，使用「匯入為獨立資料庫」。`--data-dir <路徑>` 可指定管理目錄（包含 databases.json、datasets、backups），不是單一 `.sqlite3`。附件與任務也屬於資料庫，請保存整個資料夾。

## 手術系統

- **即時刀房**：進入頁面便內嵌 `http://wmc01p:29080/EBoardWeb/opEBoardLogon`，離開此頁或切換帳號即卸載。顯示框縮小以便在同一畫面檢視；院方網頁的登入獨立處理。這部分必須在內網使用，EXE 不代理院方網站。
- **手術排程**：醫師卡號預設為目前登入帳號，可改填其他醫師卡號；按「查詢／更新」後，SDK `surgery.get_schedule` 使用目前登入的工作階段查詢所填醫師。是否可取得其他醫師的排程由院方權限決定。首次日期預設今天到兩個曆月後，包含起訖日；可修改日期或按「未來兩個月」還原。眼科科別代碼預設 `OPH`，可依院方實際代碼調整。
- 「今天及未來」由近到遠顯示；「過去」由新到舊顯示並預設收合，兩區使用不同底色。依台灣日期分區，**日期已過不代表手術完成**。無法辨識日期或回傳醫師不符的項目另列「待確認」。同一病人多筆排程各自保留。
- 可以搜尋姓名、病歷號、術式、病房、科別或刀房。清單顯示 SDK 提供的病人姓名、病房、科別、麻醉及類別；按列末圖示可檢閱手術申請單號、各筆術式、診斷等詳細欄位。院方狀態暫不顯示，也不作為搜尋條件。`TF`／`TF1` 等時間標記顯示為未定，不能當成實際開始時間。院方未提供姓名時顯示「—」，不為每筆排程另送基本資料查詢。
- 每個帳號獨立保存查詢與原始排程；相同內容共用快照，保留每次取得時間。回到頁面、篩選、收合及離線檢閱只讀本機；按「查詢／更新」才重新抓取。查詢失敗不覆蓋先前成功結果；暫停可續跑，完成五秒收起進度。
- 「爬蟲紀錄 → 查看排程」可重新開啟該次保存的結果；後來改查其他日期不會清掉原先快照。資料格式維持 1，既有病歷與刀表更新功能沿用。

## 審查查詢與監控

主表是一張持續累積的本機案件表，以帳號及案件編號區分。同病人多件申請保留各案；院方清單缺少案件不會刪除已保存資料。全部／未結案／已結案／有更新、文字、病歷號與日期篩選只查本機，不影響完整同步範圍。

- 「立即同步」或監控先呼叫 SDK `reviews.get_cases` 取得此登入帳號醫師的完整案件清單，再對本帳號尚未保存醫囑的案件呼叫 `reviews.get_orders`。第一次同步會逐件補齊歷史案件；之後只查新案及先前失敗的案件。已保存的空醫囑也視為查過，不重複請求；個案檢閱取得的醫囑同樣重用。同步可暫停與續跑，已完成案件保留。每次同步記錄新增／變更／未變更案件數，以及醫囑補查與失敗數。
- 清單的「醫囑名稱（OrderName）」顯示去重後的醫囑名稱，超過兩項可展開；「醫囑名稱」輸入框會比對任一名稱，排序可依第一個顯示名稱升冪或降冪，沒有名稱的案件排在最後。這些篩選與排序只讀取本機已保存資料，離線也可使用。「待取得」代表尚未成功讀取醫囑，「未提供」代表已讀取但院方沒有回傳 `OrderName`。
- 同意備查（1）、不予同意（2）列為已結案；其餘結果保留未結案狀態。已結案內容相同只更新核對時間，院方真的更正時仍保存差異並顯示「有更新」。
- `F` 是處理狀態「上傳完成」，不代表審查通過。各欄位優先顯示院方中文對照，未知代碼標示待辨識。
- 內容版本忽略 `UniqueID` 等暫存值，清單／明細分別比較。原有快照保留；新同步只保存版本與引用，避免每次複製整張案件表。
- 「檢閱」開啟對話框，顯示本機案件及變更歷史；完整明細、附件／PACS 索引按需取得，醫囑優先重用同步時保存的內容。按關閉、Escape 或對話框外側可回表格。
- 院內選項快取 24 小時，同步時按需取得；「監控設定 → 重新載入院內選項」可手動更新醫師、科別及狀態說明。附件／PACS 此處只顯示 SDK 提供的索引。

審查與薪資有各自的「監控設定」，預設每天一次，可輸入整數小時或天，範圍 1 小時至 30 天，也可關閉。EXE 每 30 秒檢查是否到期；僅在程式開啟、帳號登入且資料庫可編輯時執行。錯過多個週期只補一次，同類工作不重複排隊。手動暫停及重啟 EXE 前留下的工作需明確續跑；目前操作期間因院內連線失效而中斷的近期任務，連線恢復後可自動續跑。關閉監控不取消已開始的任務，可另按暫停。

## 薪資業績查詢

使用 SDK `earnings.open_performance`、`open_bonus` 與 `get_report`，保存 **醫療績點明細**及**專勤工作獎金明細**。MIS 薪資系統需要另外設定身分證字號及薪資密碼，可隨此帳號資料庫記住，換電腦不用重新設定。

1. 上方整合「薪資登入設定」「監控設定」「立即更新」「選擇期別」及最近／下次更新時間；下方是已保存報表。
2. 每次監控先確認所有仍公布的期別，再重新保存全部報表。以表格內容、結構與文字判定版本，只有 HTML 不同不會增加版本；每次實際抓取仍有紀錄。
3. 按院內期別與報表類型檢閱；保留院方原始期別，不自行減一個月當成業績月份。保留中文、原文、單位、表頭、合併儲存格與原始 HTML；畫面只顯示文字與整理後的表格，不執行院方 JavaScript。
4. 勾選報表可匯出 UTF-8 CSV 或 JSON。CSV 為逐格長表，包含報表類型、期別、年月、取得時間、版本、表格／列／欄位置、原文、可解析數值與單位；JSON 另保留完整原始內容。金額、績點、比率不混合加總。
5. 院方撤下月份不影響已保存資料。刪除會清除選取報表及所有版本，續跑與自動監控不會還原；仍可主動重新抓取院方尚提供的月份。

設定監控後只要保持主程式及帳號登入即可。薪資登入失敗不會登出院內帳號；更新密碼後可續跑。薪資報表、憑證、監控偏好與進度依帳號、資料庫分開，備份／副本一起保存；舊月份若尚未保存且院方已撤下，程式無法補回。

## 背景工作與進度

可送出多個背景工作；不同帳號可平行，同帳號的批次任務依序處理，點選延伸查詢可在安全步驟間插入。切換頁面或帳號不停止工作，各模組保留任務與結果，關閉重開後也能檢閱。

門診清單、SOAP、比較模組、病人解析、審查、薪資均在送出時立即顯示等待進度，取得任務後接上實際處理數量。分母已知時顯示已處理數量；索引／可用月份尚未確定時顯示處理中。部分失敗另列未完成數量，不把中途保存的病人算成已完成。

同一資料庫管理目錄及同一可編輯資料庫都有獨占鎖；重複啟動第二個 EXE 會被阻止。多帳號應使用同一個 EXE 管理。不同資料目錄可各自執行，但排程與任務互相獨立。

成功完成的進度區於完成時間起 5 秒自動收起，結果及爬蟲紀錄保留；失敗、部分完成、暫停保留操作入口。側欄與各系統同層級的「爬蟲紀錄」統一顯示門診、手術、審查、薪資任務及 SDK 工作階段，可續跑、重新開啟結果及查看 DEBUG 資訊。全系統固定緊湊密度。

## 帳號與門診工具

各帳號的病歷、快取、tag、集合、審查、比較結果、附件、Google 設定及院內 SDK session 完全分開。院區名稱是顯示標籤，仍使用同一高榮登入入口。不同帳號可平行請求，預設上限 3、可調 1–4；同帳號 SDK 操作依序執行。切換已連線帳號可直接沿用其 session，不中止其他帳號任務；未保存密碼的帳號只要尚未登出且 EXE 未關閉，仍可用記憶體內的憑證重連。登出會暫停該帳號任務並清除其記憶體憑證。關閉 EXE 後進度保留，重啟不自動續跑。

門診清單支援單日、區間、昨天／今天／明天。每個查詢日期一次取得整份門診清單；掛號序號直接來自同一份回傳，保留前導零，不另為每位病人查詢掛號紀錄。舊清單快取若沒有序號，可按「更新」重抓。日期分組可收合；我的門診預設全選，共用或歸屬未知的門診需另行勾選。「手動加入病人」輸入一筆病歷號或身分證號後按空白或 Enter 即開始核對；貼上多筆會分開查詢，輸入框可持續接受新號碼。查到的病人直接加入手動病人表格，預設勾選；在表格取消勾選即可移除，失敗項目可重試。已選人數顯示於表格下方。手動病人沒有掛號來源時序號顯示「未提供」，仍可用最新 SOAP 檢閱與歷年報告、醫囑、掃描等功能。病人集合以病歷號去重，保留來源；同日同病人不同掛號序號仍是不同掛號列。醫師代碼忽略最後數字後的英文尾碼，例如 AB42B 視為 AB42，但不混同 AB420；快取清單也立即適用。

左側「進階工具」標題與「選擇病人清單」同層級，其下工具縮排顯示，無須展開。「爬蟲紀錄」位於審查與薪資系統旁。少量互斥選項使用共用底框與滑動色塊，支援鍵盤方向鍵；科別、tag 超過五個選項時使用下拉選單。圖示按鈕可停留滑鼠查看用途，也有供輔助閱讀的名稱。

四種進階工具的「病人來源」在空白或 Enter 後立即核對一筆；貼上多筆會合併成任務逐位查詢，完成後自動加入目前工具。輸入完整識別號後停頓約 700 毫秒，也會自動核對。輸入法組字期間不送出，重複識別號不重複加入。數字開頭按病歷號查詢並保留前導零，英文字母開頭走 SDK 身分證核對；核對失敗不改當成病歷號。進階工具已選病人以姓名／病歷號 badge 顯示，可點選移除；「選擇病人清單」則只用表格勾選。查詢失敗可逐筆重試。從已保存集合移除或加入病人時，只更動本次工具的選取，開始工作時才另存新集合。純手動病人若選「該次門診的 SOAP」，因缺少掛號來源需改選「最新 SOAP」；其他病歷檢閱快捷功能可照常使用。資料夾圖示可搜尋及套用已保存清單，病人圖示可前往「選擇病人清單」。

**病歷檢閱**可選「最新 SOAP」或「該次門診的 SOAP」。科別關鍵字預設「眼科」，可用半形逗號、全形逗號或頓號並列，例如「眼科、病例計酬」；就診紀錄的科別名稱或代碼包含**任一**關鍵字即符合。檢閱設定依帳號保存，按「開始檢閱」直接套用。最新模式在符合科別的紀錄中取最新 SOAP，若較新紀錄空白或讀取失敗會向前補找；同日多筆全部保留。該次門診模式依所選掛號日期與科別找當次紀錄，再套用相同的關鍵字篩選。未來掛號可用來選病人，但尚未到診時無法取得當次 SOAP。

「選擇病人清單」會一次顯示所選日期範圍中符合門診歸屬標籤與搜尋條件的所有掛號，不再每 40 筆分頁；可按日期收合清單。

完成檢閱後，上方自動收成一列人數與任務狀態；「更換病人與檢閱設定」可直接展開並捲到病人來源。資料庫狀態移到側欄。左側病人清單在桌面寬 176px、較窄桌面寬 156px；清單與 SOAP 之間的小圖示可用滑鼠或鍵盤收合。清單優先顯示所選門診掛號來源的序號；舊任務可從已存掛號紀錄核對，無法唯一核對時標示「未提供」，不會為序號額外發起逐人查詢。SOAP 標題在同一列靠左顯示姓名、病歷號 badge、年齡及性別；年齡優先按生日與今天計算，缺少生日才使用院方年齡，兩者皆無標示「未提供」，不為此另發請求。點擊病歷號 badge 可複製號碼，成功後會提示；瀏覽器禁止複製時會提供可選取的號碼。標題旁的備註圖示可為本次檢閱任務中的病人加入文字，輸入後自動存進目前帳號資料庫；「批次輸出備註」會預覽本次任務所有有備註病人的掛號序號、姓名、病歷號與備註，可列印或另存 PDF。唯讀資料庫可預覽與列印備註。

標題下依序放該次數值類報告、歷年數值類報告、該次醫囑清單、歷年醫囑清單、該次掃描病歷、歷年掃描病歷、歷次就診、掛號紀錄、加入／移除 tag 快捷鍵，以及上一位／下一位；該次與歷年的圖示分別有單日與時鐘標記。同一病人本次有多份 SOAP 時，該次查詢會先讓使用者選擇就診。自動與手動 TAG 分組顯示；自動 TAG 和搜尋命中的徽章可跳到 SOAP 依據或關鍵字，搜尋字串在結構化 SOAP 與完整原文中以底色標示。切換到其他系統後再按側欄「病歷檢閱」，會回到同一份結果與病人，不會重新抓取；重新開啟程式則載入該帳號最近一次檢閱。點擊「更換病人與檢閱設定」可直接調整來源與條件；保存新的抓取範圍後按「開始新檢閱」，原任務與病歷保留；取消或 Escape 關閉設定則還原未保存的修改。

「歷年掃描病歷」先顯示已保存的完整掃描索引，預設篩選院方「門診-記錄-眼科紀錄」類別；可切換「全部類別」、任何院方病歷類別或「類別未提供」，並用類別、日期與就診資料搜尋。RECORD／OPG 是 PDF 來源 subtype，不代表科別；其他類別（例如術前標示同意書）不會僅因 OPG 而列為眼科紀錄。舊版索引可離線查看，連線後會補上新版類別與日期。若需要核對單次 SOAP 的掃描參照，可按「補查眼科就診連結」逐次查詢，歷年類別清單本身不需要這個步驟。開啟掃描時，左側保留清單與篩選，右側顯示 PDF。PDF 在開啟或加入比較時才下載並保存在目前帳號，可離線重看。醫囑 PDF／影像及掃描 PDF 可先加入同一個比較清單，最多六份；按「查看比較」才開啟工作區，檔案依數量自動排列，窄螢幕以分頁切換。檢閱與白內障術前可保留同一病人的比較選取，切換病人或帳號會清空；選取只存在本次程式畫面。

兩種模式都只檢查截至執行當天的門診就診，不納入住院或未來紀錄；檢閱設定不需另選截至日期。舊版檢閱任務保留當時的日期與科別範圍，續跑也會沿用原設定；新檢閱使用科別字串。

取得方式預設重用有效的已存 SOAP 與就診索引；快取過期或資料缺漏時才補抓。只有勾選「重新下載病歷」，本次檢閱才會重新查詢就診索引並下載 SOAP，適合院內病歷已修訂時使用；舊版本保留。此勾選只對本次執行有效，不會保存為下一次檢閱的預設值。

文字、regex、tag 搜尋限於本次任務採用的 SOAP。預設自動 tag：手術 `# Arrange`、審查 `# APPLY`；可在模組內修改與重新分類。手動 tag 以病人為單位，和自動命中分開。歷年數值、醫囑及就診先讀同帳號已存索引，沒有快取才查院內；選取某次舊門診才抓該次 SOAP、數值或醫囑，且不改動目前檢閱或 TAG。數值歷史索引約涵蓋最近 10 年、醫囑約 11 年，更早仍有就診索引的門診可逐次補查。醫囑合併一般與手術類索引並去重，含所有科別。歷年醫囑預設依名稱分類，可切換日期排序與搜尋；該次醫囑維持原有日期排序。選取醫囑後才取得文字、PDF 或影像報告。住院與急診列出基本資料，但此處無法開啟 SOAP。掛號依查詢基準日分為今天及未來／過去，各區日期由新到舊，日期不明另列；保留取消狀態，不視為實際到診。索引快取 5 分鐘、當日 SOAP／掛號快取 60 秒；歷史資料重用本機版本，修訂時可按「更新資料」重抓。

SOAP 使用目前鎖定的 SDK 結構化欄位：病歷檢閱依 A+P、O、S 順序分段顯示，再顯示診斷、藥囑、醫囑、其他原文與完整原文；並保留慢性處方明示的服藥期限及解析問題。來源只有 A+P 時不硬拆為 A／P；原本分開的 A、P 仍各自呈現。藥囑與醫囑是 SOAP 列印摘要，不代表執行狀態，也不會額外查詢醫囑頁面。同一病人就診清單若含舊病歷號，病歷檢閱會以該次就診的原始號碼取得 SOAP 與單次數值報告。數值表的欄名依 SDK 的逐欄路徑顯示；無法安全對齊的表格保留原始順序供核對。

「檢閱設定 → 自動 tag」中，每個 tag 可選 **全文、S、O、A+P、藥囑、醫囑**。內建「手術：`# Arrange`」與「審查：`# APPLY`」預設在 **A+P** 辨識，包含來源獨立標示的 A、P。既有帳號已保存的範圍保留；修改規則並保存時，已完成的當前檢閱會用本機 SOAP 自動重新分類，不需連線院內。關鍵字以文字比對，不視為 regex；管理已儲存病歷的查詢會直接套用現行規則。手動 tag 不受辨識範圍影響。

未取得該區塊或摘要解析不完整時顯示「tag 判定不完整」，不改用全文補判。舊版病歷未保存結構資料，仍可檢閱原文與使用全文 tag；要補齊分段，需針對同次就診選「重新下載病歷」。只改規則、搜尋或開啟病歷不會自動重抓。

| 比較工具 | 數值 | 醫囑／報告 |
| --- | --- | --- |
| 視網膜比較 | Va | Fundus Color Photo Picture, eac；Microsonography；FAG |
| 白內障術前分析 | Va、VacC、驗光-散瞳前、IOP-pneumo、Endothelial No、KM | DBR, free charge；Photokeratoscopy (color)；FUNCTIONAL VISUAL ANALYSIS；Keratomery；Corneal Endothelial Microscopy |

白內障術前分析進入後，依清單順序背景取得歷年數值、醫囑索引和最新可讀的眼科門診 SOAP；先呈現已存資料，不顯示日期範圍。左側清單顯示每位病人狀態，失敗任務可續跑，也能明確按更新。新病人先顯示 **SOAP**；看完可切換到 **數值與醫囑**，再進入 **報告比較**，同一位病人可隨時返回 SOAP。切換檢視不會增加院內爬蟲請求。

數值欄把 Va、VacC、驗光-散瞳前、IOP-pneumo、Endothelial No、KM 分成六組，各組列出筆數與最新讀數；可同時展開多組，組內日期由新到舊，同日多筆分開，原始表格可逐筆開啟。本次程式使用期間，同一病人的展開狀態會保留。右側醫囑按名稱分組，DBR 排在最前；五類醫囑只抓索引，選取一筆才讀取其報告與附件。報告在頁面內預覽，勾選附件只是加入比較清單，按「查看比較」才切換檢視。

比較檢視保留可收合的數值欄，檔案依剩餘寬度自動排列；PDF／影像可獨立捲動、縮放、換位及移除，最多六份。窄畫面可切換數值、醫囑與檔案；切換病人或帳號會清空比較選取。其他分析模組仍可設定比較期間。左右眼、同日多筆、特殊 VA、原文與單位保留；相同量測／單位／側別才繪圖。數值索引最多 3,650 日、醫囑 4,000 日，以就診索引補查更早且 SDK 支援的門診；不足處列出供人工確認。

刀表更新仍從門診進階工具開啟，以 `# Arrange` 病歷建立候選、補充院內資料，先逐格預覽，明確按「套用更新」才寫入並讀回核對。保留公式、人工欄位及 CalendarEventId。參考 [Google 設定](GOOGLE_SHEETS_SETUP.md)。

「管理已儲存病歷」可依文本、tag、就診日期及來源任務搜尋、重新建立集合或刪除。刪除 SOAP 會移除其版本與任務引用並阻止舊任務還原；獨立比較資料與手動 tag 保留。移除集合不等於刪除病歷。

病歷列依序顯示姓名、病歷號、就診日期、科別，下方顯示 A／P 精簡預覽。點擊資料列開啟完整 SOAP；勾選框僅供選取，不會開啟病歷。點檢閱框外側、關閉鈕或按 Escape 都可關閉並回到原資料列。

A+P 預覽優先使用已保存的 SDK `assessment_plan` 欄位；來源分別標示 A、P 時則顯示各自內容，明確空白與未辨識分開呈現。舊資料只從明確文字標題辨識，沒有標題就顯示提示，不依區塊位置猜測。讀取預覽只查本機，不會重新爬取或改寫資料；新抓取的結構與原文一併保存於原本 SQLite 的病歷版本，不需搬移資料庫。

## 院內重試與診斷

就診索引遇到 `PRQ_CASE_PATIENT_MISMATCH` 時，程式會在同一帳號的序列操作內重建病人上下文、核對標頭，且僅在尚未送出調閱原因時重試一次；仍不符就不抓取或保存可疑 SOAP。院方要求調閱病歷審查時，SDK 會核對病歷號、登入資訊與表單；只有表單提供「了解病情」才自動送出醫療用途原因，確認接受後繼續讀取 SOAP。若原因未提供、院方未接受或送出結果不明，會停止並記錄錯誤，不重複送出。院方 session 過期時，PRQ／醫囑安全讀取由 SDK 在調閱送出前自行重登；其他安全讀取可由帳號工作區用記憶體憑證重建連線一次。仍無法連線時畫面會提示並以 15 秒起、最長 2 分鐘的間隔再試；若帳密遭拒或沒有可用密碼，會在原畫面要求更新該帳號密碼。恢復後可續跑近期因連線失效暫停的任務；登出、明確離線檢閱及非讀取操作不自動重送。檢閱病人可按「重試此病人」；詳細錯誤與 SDK 互動可從「爬蟲紀錄 → DEBUG 資訊」查詢及匯出 JSON。

診斷自動保存在**目前資料庫資料夾內**，不依賴原電腦：

- `accounts/<帳號代碼>/clinical.sqlite3`：`bot_documents` 的 `patient_diagnostic` 保存任務、時間、EXE／SDK 版本、目標病歷號、就診、階段、錯誤碼、HTTP 狀態及程式位置。`bot_sdk_events` 保存每次 SDK 互動的服務、方法、時間、結果及安全的錯誤摘要，包含登入與四個系統的抓取。索引身分核對另保存標頭／回應病歷號與重試結果；舊任務的錯誤摘要仍可查閱。
- `accounts/<帳號代碼>/diagnostics/<工作階段代碼>/diagnostics.jsonl`：實際 SDK 登入與後續請求的時間、端點路徑、狀態碼、重試／重新登入及回應結構，例如字元編碼、表格與 SOAP 元素是否存在。逐筆寫入；登出或結束程式後另有 `summary.json`。SDK 日誌時間使用 UTC。
- 不保存原始回應正文、密碼、Cookie、權杖或請求欄位值；程式位置不包含本機變數。重試成功不清除舊診斷，資料庫備份、複本與匯入會一併保存。

使用「結束程式」後，把 EXE 與整個 `VGHKS-bot-data` 一起帶回即可診斷；若使用外部資料庫位置，也需攜帶該資料庫資料夾。畫面的「DEBUG 資訊」顯示最近 200 次 SDK 互動、最近 100 筆符合的錯誤細節及已保存嘗試，完整 SDK 日誌仍在上述資料夾。舊版沒有保存的詳細資訊不能補回，需使用新版在院內重新抓取。
