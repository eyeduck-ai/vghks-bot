# 操作說明

Windows 單檔 EXE，本機瀏覽器介面。系統入口：**門診、審查查詢、薪資業績查詢、手術**。

## 開始使用

1. 執行下載的 `VGHKS-bot.exe`。更新既有程式時，先關閉舊程式，再以新版 EXE 取代，讓 EXE 與原有 `VGHKS-bot-data` 資料夾保持同層，即可沿用資料。首次使用才建立空白資料庫並輸入院內帳密；成功後預設保存，下次驗證上次帳號。
2. 從「選擇病人清單」勾選病人，再按對應工具；也可直接從左側進階工具輸入一個病歷號／身分證，核對後使用。各工具也能套用已保存集合。
3. 審查查詢系統：按「立即同步」取得此帳號醫師的完整清單，再以本機篩選檢閱。全部案件在同一頁，以表格捲動檢閱，不分頁。
4. 薪資業績查詢：設定薪資登入資訊 →「立即更新」保存目前公布期別 → 檢閱或匯出報表。
5. 手術系統：即時刀房可開啟院內看板；手術排程依登入帳號查詢，預設今天至兩個月後，可修改日期。
6. 「資料庫管理」可從登入頁或左側開啟，不必先連上院內。

本版使用資料格式 1，不讀取或轉換格式 1 之前的資料庫與 DPAPI 憑證。原有檔案不會自動刪除；首次使用空白資料庫需設定帳號與 Google 金鑰。

## 資料庫管理

| 操作 | 行為 |
| --- | --- |
| 建立新資料庫 | 建立空白、獨立的資料庫；名稱可自訂，路徑留白使用預設資料目錄 |
| 開啟資料夾 | 指定含 `database.json` 的資料夾，選擇一般使用或唯讀檢閱 |
| 唯讀檢閱 | 在暫存副本查看已保存內容，禁止登入、抓取及修改，不改動來源 |
| 建立備份 | 保存帳號、憑證、病歷、審查、任務、設定及附件；備份固定以唯讀開啟 |
| 建立可編輯副本 | 從目前資料庫或備份建立另一份，可開啟後繼續工作 |
| 匯入為獨立資料庫 | 先預覽帳號／病歷／審查／附件數量，再複製至本機；不合併內容、不改動來源 |
| 重新命名 | 修改顯示名稱，資料夾位置不變 |
| 移出清單 | 移除管理清單的捷徑，原始資料夾保留 |

切換、複製、備份前請暫停所有帳號任務，並等目前查詢完成。目的資料夾必須不存在，不覆寫既有資料。資料庫切換後重新載入頁面，避免舊頁面寫入新資料庫。

EXE 版本與資料格式分開管理；本版資料格式為 **1**。開啟／匯入會檢查格式與 SQLite 完整性，不支援的格式直接拒絕，不自動升級。如果上次的資料庫已移走或格式不符，仍可進入資料庫管理，選擇其他資料庫。要查看目前格式的歷史狀態，開啟該備份；要繼續修改，先建立可編輯副本。未來若資料格式改變，需使用支援該格式的 EXE；本版不提供跨格式轉換。

## 隨身碟與儲存位置

預設資料位於 **EXE 同層的 `VGHKS-bot-data`**：

```text
VGHKS-bot.exe
VGHKS-bot-data/
  databases.json                         資料庫清單及上次開啟位置
  datasets/<資料庫目錄>/
    database.json                        名稱、識別碼、資料格式
    accounts.sqlite3                     帳號、可攜式密碼與偏好
    accounts/<帳號代碼>/
      clinical.sqlite3                   病歷、審查追蹤、薪資報表、集合、任務與可攜式憑證
      diagnostics/<工作階段代碼>/         SDK 請求診斷 JSONL 與結束摘要
      assets/<SHA-256>                    PDF／影像
      runs/                              抓取任務日誌
      settings.json                      tag 與請求設定
  backups/<備份目錄>/                     完整資料庫備份
```

使用側欄「結束程式」後，攜帶 **EXE + 整個 `VGHKS-bot-data`** 即可換電腦使用，不需重輸密碼或重新匯入 Google 金鑰。資料庫中的憑證與解密資料一同保存，不綁定 Windows 使用者；持有整份資料的人能使用這些憑證。密碼與私鑰不回傳瀏覽器或寫入任務日誌。

「開啟資料夾」可以指向外部位置；外部資料不會跟著預設目錄移動。若要一起攜帶，使用「匯入為獨立資料庫」。`--data-dir <路徑>` 可指定管理目錄（包含 databases.json、datasets、backups），不是單一 `.sqlite3`。附件與任務也屬於資料庫，請保存整個資料夾。

## 手術系統

- **即時刀房**：「開啟院內刀房」以新分頁開啟 `http://wmc01p:29080/EBoardWeb/opEBoardLogon`；「在此頁開啟」才載入 iframe，離開此頁、關閉內嵌或切換帳號即卸載。院方網頁的登入獨立處理；若因院方內嵌限制、瀏覽器或登入限制而空白，使用新分頁連結。這部分必須在內網使用，EXE 不代理院方網站。
- **手術排程**：按「查詢／更新」呼叫 SDK `surgery.get_schedule`，固定使用目前登入帳號。首次日期預設今天到兩個曆月後，包含起訖日；可修改日期或按「未來兩個月」還原。眼科科別代碼預設 `OPH`，可依院方實際代碼調整。
- 「今天及未來」由近到遠顯示；「過去」由新到舊顯示並預設收合，兩區使用不同底色。依台灣日期分區，**日期已過不代表手術完成**；取消與其他院方狀態保留。無法辨識日期或回傳醫師不符的項目另列「待確認」。同一病人多筆排程各自保留。
- 可以搜尋姓名、病歷號、術式或刀房，按列末圖示檢閱原始欄位。院方未提供姓名時顯示「—」，不為每筆排程另送基本資料查詢。
- 每個帳號獨立保存查詢與原始排程；相同內容共用快照，保留每次取得時間。回到頁面、篩選、收合及離線檢閱只讀本機；按「查詢／更新」才重新抓取。查詢失敗不覆蓋先前成功結果；暫停可續跑，完成五秒收起進度。
- 「任務紀錄 → 查看排程」可重新開啟該次保存的結果；後來改查其他日期不會清掉原先快照。資料格式維持 1，既有病歷與刀表更新功能沿用。

## 審查查詢與監控

主表是一張持續累積的本機案件表，以帳號及案件編號區分。同病人多件申請保留各案；院方清單缺少案件不會刪除已保存資料。全部／未結案／已結案／有更新、文字、病歷號與日期篩選只查本機，不影響完整同步範圍。

- 「立即同步」或監控會呼叫 SDK `reviews.get_cases`，查詢此登入帳號醫師的完整案件清單，不逐件抓取未結案明細。每次同步保存時間、成功／失敗與新增／變更／未變更數量。
- 同意備查（1）、不予同意（2）列為已結案；其餘結果保留未結案狀態。已結案內容相同只更新核對時間，院方真的更正時仍保存差異並顯示「有更新」。
- `F` 是處理狀態「上傳完成」，不代表審查通過。各欄位優先顯示院方中文對照，未知代碼標示待辨識。
- 內容版本忽略 `UniqueID` 等暫存值，清單／明細分別比較。原有快照保留；新同步只保存版本與引用，避免每次複製整張案件表。
- 「檢閱」開啟右側抽屜，顯示本機案件及變更歷史；完整明細、醫囑、附件／PACS 索引按需取得。按關閉、Escape 或抽屜外側可回表格。
- 院內選項快取 24 小時，同步時按需取得；「監控設定 → 重新載入院內選項」可手動更新醫師、科別及狀態說明。附件／PACS 此處只顯示 SDK 提供的索引。

審查與薪資有各自的「監控設定」，預設每天一次，可輸入整數小時或天，範圍 1 小時至 30 天，也可關閉。EXE 每 30 秒檢查是否到期；僅在程式開啟、帳號登入且資料庫可編輯時執行。錯過多個週期只補一次，同類工作不重複排隊。暫停或上次中斷的工作需明確續跑；關閉監控不取消已開始的任務，可另按暫停。

## 薪資業績查詢

使用 SDK `earnings.open_performance`、`open_bonus` 與 `get_report`，保存 **醫療績點明細**及**專勤工作獎金明細**。MIS 薪資系統需要另外設定身分證字號及薪資密碼，可隨此帳號資料庫記住，換電腦不用重新設定。

1. 上方整合「薪資登入設定」「監控設定」「立即更新」「選擇期別」及最近／下次更新時間；下方是已保存報表。
2. 每次監控先確認所有仍公布的期別，再重新保存全部報表。以表格內容、結構與文字判定版本，只有 HTML 不同不會增加版本；每次實際抓取仍有紀錄。
3. 按院內期別與報表類型檢閱；保留院方原始期別，不自行減一個月當成業績月份。保留中文、原文、單位、表頭、合併儲存格與原始 HTML；畫面只顯示文字與整理後的表格，不執行院方 JavaScript。
4. 勾選報表可匯出 UTF-8 CSV 或 JSON。CSV 為逐格長表，包含報表類型、期別、年月、取得時間、版本、表格／列／欄位置、原文、可解析數值與單位；JSON 另保留完整原始內容。金額、績點、比率不混合加總。
5. 院方撤下月份不影響已保存資料。刪除會清除選取報表及所有版本，續跑與自動監控不會還原；仍可主動重新抓取院方尚提供的月份。

設定監控後只要保持主程式及帳號登入即可。薪資登入失敗不會登出院內帳號；更新密碼後可續跑。薪資報表、憑證、監控偏好與進度依帳號、資料庫分開，備份／副本一起保存；舊月份若尚未保存且院方已撤下，程式無法補回。

## 背景工作與進度

可送出多個背景工作；不同帳號可平行，同帳號的批次任務依序處理，點選延伸查詢可在安全步驟間插入。切換頁面或帳號不停止工作，各模組保留任務與結果，關閉重開後也能檢閱。

門診清單、SOAP、比較模組、病人解析、審查、薪資均顯示進度。分母已知時顯示已處理數量；索引／可用月份尚未確定時顯示處理中。部分失敗另列未完成數量，不把中途保存的病人算成已完成。

同一資料庫管理目錄及同一可編輯資料庫都有獨占鎖；重複啟動第二個 EXE 會被阻止。多帳號應使用同一個 EXE 管理。不同資料目錄可各自執行，但排程與任務互相獨立。

成功完成的進度區於完成時間起 5 秒自動收起，結果及任務紀錄保留；失敗、部分完成、暫停保留操作入口。「任務紀錄」用於續跑與重新開啟結果。全系統固定緊湊密度。

## 帳號與門診工具

各帳號的病歷、快取、tag、集合、審查、比較結果、附件及 Google 設定完全分開。院區名稱是顯示標籤，仍使用同一高榮登入入口。不同帳號可平行請求，預設上限 3、可調 1–4；同帳號 SDK 操作依序執行。切換帳號不中止其他帳號任務；登出會暫停該帳號任務。關閉 EXE 後進度保留，重啟不自動續跑。

門診清單支援單日、區間、昨天／今天／明天。日期分組可收合；我的門診預設全選，共用或歸屬未知的門診需另行勾選。手動加入病人會先取得基本資料核對，解析失敗不加入。病人集合以病歷號去重，保留來源。醫師代碼忽略最後數字後的英文尾碼，例如 AB42B 視為 AB42，但不混同 AB420；快取清單也立即適用。

左側「進階工具」標題與「選擇病人清單」「任務紀錄」同層級，其下工具縮排顯示，無須展開。少量互斥選項使用共用底框與滑動色塊，支援鍵盤方向鍵；科別、tag 超過五個選項時使用下拉選單。圖示按鈕可停留滑鼠查看用途，也有供輔助閱讀的名稱。

四種工具的病人來源均可直接輸入一筆病歷號或身分證字號，按 Enter 或放大鏡查詢。數字開頭按病歷號查詢並保留前導零，英文字母開頭走 SDK 身分證核對；核對失敗不改當成病歷號。先確認姓名等基本資料，再按「使用此病人」。輸入框右側的資料夾圖示可搜尋及套用已保存清單，病人圖示可前往「選擇病人清單」。

**病歷檢閱**預設最新同科 SOAP。「檢閱設定」集中科別篩選、SOAP 篩選、時間與取得方式、自動 tag 及科別群組對應，設定依帳號保存。可切換「不限科別」取得最新門診 SOAP，或使用「掛號當次」依所選掛號日期與科別取得當次紀錄。未來掛號可用來選病人，不限制歷史分析範圍。最新紀錄空白或讀取失敗會向前補找，顯示實際採用日期與較新紀錄狀態；同日多筆全部保留。

按「開始檢閱」後，上方收成一列摘要，下方直接檢閱病人及 SOAP。「更換病人」圖示可重新展開來源；「檢閱設定」圖示開啟設定視窗。保存新的抓取範圍後可按「開始新檢閱」，原任務與病歷保留；取消或 Escape 關閉設定則還原未保存的修改。從任務紀錄重新開啟時也預設收起病人來源。

科別群組用於限定「同科別」的查找範圍。手動病人或已對應的同科來源不需額外勾選；來源含其他科別、未知代碼或缺少科別時才要求確認，畫面會列出原因。在「檢閱設定 → 科別群組對應」保存確認過的代碼／別名後，同類來源便不再重複詢問。「不限科別」不以科別過濾，但仍限定截至指定日期的門診，不納入住院或未來紀錄。「掛號當次」直接按來源日期及科別查找，不需確認群組。

| 取得方式 | 用途 |
| --- | --- |
| 重用已存病歷（預設） | 重用已存 SOAP 與有效索引；快取過期或缺漏時補抓。日常檢閱使用此選項。 |
| 檢查新紀錄 | 立即重新查就診索引、補抓新就診及缺漏；有效的歷史 SOAP 繼續重用。 |
| 重新下載病歷 | 重新查索引並下載 SOAP，適合院內病歷已修訂時使用；舊版本保留。 |

文字、regex、tag 搜尋限於本次任務採用的 SOAP。預設自動 tag：手術 `# Arrange`、審查 `# APPLY`；可在模組內修改與重新分類。手動 tag 以病人為單位，和自動命中分開。本次數值報告、掛號紀錄在點選後才取得。掛號依查詢基準日分為今天及未來／過去，各區日期由新到舊，日期不明另列；保留取消狀態，不視為實際到診。索引快取 5 分鐘、當日 SOAP／掛號快取 60 秒；歷史資料在跨日確認後重用，修訂時可強制重抓，舊版本保留。

SOAP 使用 SDK 0.20.0 的結構化欄位：S、O、A+P 分段顯示，診斷、藥囑及醫囑以表格整理，並保留慢性處方明示的服藥期限、未分類內容、完整原文與解析問題。來源只有 A+P 時不硬拆為 A／P；原本分開的 A、P 仍各自呈現。藥囑與醫囑是 SOAP 列印摘要，不代表執行狀態，也不會額外查詢醫囑頁面。

「檢閱設定 → 自動 tag」中，每個 tag 可選 **全文、S、O、A+P、藥囑、醫囑**。內建「手術：`# Arrange`」與「審查：`# APPLY`」預設在 **A+P** 辨識，包含來源獨立標示的 A、P。既有帳號已保存的範圍保留；可在此設定改成 A+P，再按「套用目前 tag」圖示重新分類本次結果，不需連線院內。關鍵字以文字比對，不視為 regex；管理已儲存病歷的查詢會直接套用現行規則。手動 tag 不受辨識範圍影響。

未取得該區塊或摘要解析不完整時顯示「tag 判定不完整」，不改用全文補判。舊版病歷未保存結構資料，仍可檢閱原文與使用全文 tag；要補齊分段，需針對同次就診選「重新下載病歷」。只改規則、搜尋或開啟病歷不會自動重抓。

比較期間與門診日期獨立。左右眼、同日多筆、特殊 VA、原文與單位保留；相同量測／單位／側別才繪圖。數值索引最多 3,650 日、醫囑 4,000 日，以就診索引補查更早且 SDK 支援的門診；不足處列出供人工確認。

刀表更新仍從門診進階工具開啟，以 `# Arrange` 病歷建立候選、補充院內資料，先逐格預覽，明確按「套用更新」才寫入並讀回核對。保留公式、人工欄位及 CalendarEventId。參考 [Google 設定](GOOGLE_SHEETS_SETUP.md)。

「管理已儲存病歷」可依文本、tag、就診日期及來源任務搜尋、重新建立集合或刪除。刪除 SOAP 會移除其版本與任務引用並阻止舊任務還原；獨立比較資料與手動 tag 保留。移除集合不等於刪除病歷。

病歷列依序顯示姓名、病歷號、就診日期、科別，下方顯示 A／P 精簡預覽。點擊資料列開啟完整 SOAP；勾選框僅供選取，不會開啟病歷。點檢閱框外側、關閉鈕或按 Escape 都可關閉並回到原資料列。

A+P 預覽優先使用已保存的 SDK `assessment_plan` 欄位；來源分別標示 A、P 時則顯示各自內容，明確空白與未辨識分開呈現。舊資料只從明確文字標題辨識，沒有標題就顯示提示，不依區塊位置猜測。讀取預覽只查本機，不會重新爬取或改寫資料；新抓取的結構與原文一併保存於原本 SQLite 的病歷版本，不需搬移資料庫。

## 院內重試與診斷

就診索引遇到 `PRQ_CASE_PATIENT_MISMATCH` 時，程式會在同一帳號的序列操作內重建病人上下文、核對標頭，再重試一次；仍不符就不抓取或保存可疑 SOAP。檢閱病人可按「重試此病人」及「查看診斷」；任務紀錄中的失敗／部分完成／待續跑任務，以及延伸資料失敗頁，也有診斷入口，可匯出 JSON。

診斷自動保存在**目前資料庫資料夾內**，不依賴原電腦：

- `accounts/<帳號代碼>/clinical.sqlite3`：`bot_documents` 的 `patient_diagnostic` 保存任務、時間、EXE／SDK 版本、目標病歷號、就診、階段、錯誤碼、HTTP 狀態及程式位置。索引身分核對另保存標頭／回應病歷號與重試結果；舊任務的錯誤摘要仍可查閱。
- `accounts/<帳號代碼>/diagnostics/<工作階段代碼>/diagnostics.jsonl`：實際 SDK 登入與後續請求的時間、端點路徑、狀態碼、重試／重新登入及回應結構，例如字元編碼、表格與 SOAP 元素是否存在。逐筆寫入；登出或結束程式後另有 `summary.json`。SDK 日誌時間使用 UTC。
- 不保存原始回應正文、密碼、Cookie、權杖或請求欄位值；程式位置不包含本機變數。重試成功不清除舊診斷，資料庫備份、複本與匯入會一併保存。

使用「結束程式」後，把 EXE 與整個 `VGHKS-bot-data` 一起帶回即可診斷；若使用外部資料庫位置，也需攜帶該資料庫資料夾。畫面的「查看診斷」顯示資料庫內的最近 100 筆符合紀錄及已保存嘗試，完整 SDK 日誌仍在上述資料夾。舊版沒有保存的詳細資訊不能補回，需使用新版在院內重新抓取。
