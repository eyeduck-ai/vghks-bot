## 人工介面驗證

確認各系統與獨立工具頁沒有底部提示區，病歷檢閱及桌面工具充分使用可用高度，窄螢幕可捲動且沒有水平溢出。資料庫名稱、模式及路徑可從管理視窗查看；重新命名、切換與唯讀開啟後，入口提示及同列唯讀標記一致。「結束程式」按鈕提供滑鼠提示與輔助閱讀描述，正常離開前仍完成備註及草稿儲存。

兩處手動輸入以空白、Enter、連續輸入和多行貼上檢查立即核對；進階工具另檢查停頓約 700 毫秒後自動核對及輸入法組字。選擇病人清單使用表格勾選或取消手動病人，進階工具仍可用病人 badge 移除，失敗項目可重試。檢查大清單的表格與進階工具 badge 可捲動瀏覽、鍵盤操作，以及已存集合編輯後仍保留原集合與掛號來源。任務送出時立即顯示等待進度；用無掛號來源的病人確認序號顯示「未提供」且最新 SOAP 可開啟。

使用 `tools/browser_bot_fixture.py --followup --library --local-board`，確認帳號切換、病人集合、工具設定、SOAP／tag、TAG 徽章定位、病人清單 176／156px 與小螢幕收合、靠左標題及病歷號複製、歷史資料對話框、切換系統後返回最近檢閱、搜尋、進度自動收起及刀房 iframe 載入／卸載。以合成資料檢查備註入口緊鄰 TAG、展開與自動儲存、重開後保留、帳號／任務隔離、序號缺值與歧義、批次列印預覽，以及生日當天、隔天生日與缺值顯示。檢查審查和薪資查詢列在桌面與窄螢幕可操作。確認該次／歷年掃描入口、醫囑與掃描 PDF／影像並排比較、跨功能保留、切換病人清空，以及鍵盤與窄螢幕單頁切換。比較模組與刀表另用合成 fixture 驗證，不連真實 Google 刀表。

使用 `--library --ophthalmic --local-board` 追加驗證不同日期的單份 PDF 標題、同日兩份 PDF 的序號、先選檔案 2 的來源序號、移位與縮放、24×24 控制與窄螢幕分頁；以正負驗光、零值、SE 與 KM 檢查分析、比較側欄及檢閱數值的加號與淡色標籤。原始資料仍可逐字核對。

## 院內驗收

白內障數值另檢查窄面板的「日期｜OD｜OS」、驗光兩列、KM 三列（K1／K2 半徑以括弧標示、Kavg 與 CYL 同列）及日期共用格；K1、K2、Sph、Cyl 固定兩位小數，整數如 42 顯示 42.00；SE 範例應為 −1.75，Kavg 為 41.875。無資料項目不列出，無法解析時仍能核對原文。同日多筆分列；比較與 ZIP 的數值一致。切換功能頁恢復原檢視，數值更新或收合不重新載入醫囑 PDF／影像。所有分頁頂端沒有重複資料庫提示，窄螢幕仍可從側邊查看可編輯／唯讀狀態，啟動按鈕靠左。

1. 每個院區帳號登入及讀取權限；中文姓名、科別、醫師尾碼及身分證解析。
2. 預設「眼科」與「眼科、病例計酬」多關鍵字任一符合的科別名稱／代碼比對、最新／該次門診 SOAP、舊任務單字設定、空白補找、初診與權限失敗區分；特殊報告、左右眼與歷史涵蓋期間。
3. 新版門診清單的實際序號與前導零、舊快取更新，以及備註列印版面在臨床印表機的呈現。
4. 長時間連線、院方工作階段過期及每日監控實際更新。
5. 手術排程姓名／科別、日期範圍、本人與其他醫師卡號的院方授權及實際清單；即時刀房登入及 iframe 相容性。
6. 在刀表副本測試欄位對應、改期及 Google 寫入權限，確認後再使用正式刀表。
7. 實際院內掃描病歷的完整類別與日期、眼科紀錄和術前標示同意書區分、舊病歷號、選用的眼科就診連結核對與 PDF 下載；合成資料無法取代院內回應驗證。
8. 聯醫帳號的門診掛號紀錄在登入後與查過病人基本資料後皆可讀取；遇到真實病歷調閱審查時，核對只送出一次醫療用途原因且後續 SOAP 能繼續。若院方未提供該原因或未確認送出，應停止並在「爬蟲紀錄」檢查錯誤，不自動重送。
9. 白內障先呈現已保存 SOAP 與數值，再處理醫囑；背景病人有間隔。手動點選另一位時，現有讀取保存後切換；暫停／登出後不自動恢復。使用「繼續」核對成功內容不重抓，失敗與清除資料需明確續跑／更新。
10. 在九人以上集合中快速連續切換，核對姓名、病歷號、SOAP 與數值一致；已完成病人不出現「安排背景抓取」。重訪、切頁返回及背景新資料保存後均能正常顯示。HAR 僅保留本機分析，分享前移除病歷及驗證資訊；院內實際耗時需以新版 EXE 再測。

院內失敗時可從「爬蟲紀錄」開啟「DEBUG 資訊」。SDK 互動摘要與診斷跟著本機資料庫保存，詳細 SDK 日誌在帳號 `diagnostics/`；不要把真實病歷、身分證、帳密或完整診斷直接貼到公開 Issue。

### 解析失敗 DEBUG（6.6.31）

- 合成醫囑頁重現 `JS_EXPRESSION_UNSUPPORTED`，核對全部類別／手術類兩份索引、HTTP 200、端點、解析位置、出錯欄位與保留資料值的表達式。SDK 互動、任務未完成項目與診斷不重複計算為更多失敗。
- 失敗的索引不存為成功空結果；SOAP 與數值保留，續跑不重抓成功項目。舊紀錄顯示查詢類別與原始語法未記錄；模組名稱可從舊分析設定恢復，分析任務已移除誤跳視網膜的結果入口。
- 完整 DEBUG ZIP 的 `.bin` 與 `.html` 保留原始醫療值，可由相同 SDK 重現錯誤。驗證跨帳號隔離、登入驗證、唯讀下載、離線副本、檔名越界拒絕及缺檔標示；請求送出的密碼與 Cookie 標頭值不進 SDK 時序。
- 院內驗收：以新版對原失敗病人按續跑，從對應任務下載完整 DEBUG ZIP，確認原始來源可重現真正的未支援語法。使用者提供的 6.6.28 紀錄沒有原始頁面，不能由該紀錄確認確切表達式或宣稱此 SDK 格式問題已修復。
