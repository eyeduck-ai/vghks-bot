# 驗證與院內驗收

公開測試全部使用合成病人、一次性測試金鑰與暫存資料庫，不含實測病歷或院內帳密。CI 與本機都執行 `tools/run_checks.py --build`。

## 自動驗證

- 來源發布範圍、版本標籤、SDK lock 一致性、公開登入預設值。
- Python 單元／整合測試、Ruff、JavaScript 語法及依賴檢查。
- 帳號隔離、SOAP 病人上下文、結構化 SOAP、tag 區塊、日期與快取。
- 已核對病人名下的舊病歷號就診、原始號碼 SOAP／單次數值報告，以及不符病人的拒收。
- 多筆手動病歷號的核對、去重、整批建立病人集合；沒有掛號來源時仍可用最新 SOAP 檢閱。
- SDK 0.20.11：專案合成測試驗證病人調閱審查只送出一次院方提供的「了解病情」原因，確認後才讀就診清單；病人核對失敗、原因缺少或回覆不明時不重送。另以 SDK 原廠合成測試驗證聯醫 WebMAAS SSO 與掛號清單；實際院內回應仍列於下方人工驗收。
- SDK 0.20.5 門診清單掛號序號的前導零、快取/API 傳遞、舊快取缺值、同日同病人不同序號的獨立選取及病歷檢閱來源序號。
- 數值表逐欄路徑的左右眼順序、手填異常值保留，以及表頭無法對齊時停止推測欄位。
- 歷史資料的帳號與病人範圍、已核對的舊病歷號及就診／醫囑識別碼、跨索引去重、按需讀取文字／PDF／影像、離線快取及歷史 SOAP 不改動目前檢閱。
- 掃描病歷：完整類別索引、眼科類別與 PDF subtype 區分、顯示日期、重複參照去重、舊索引升級、損壞索引與就診連結補救、失敗保留快取、舊病歷號、舊 SOAP 快取、逐次核對續跑、未核對檔案拒收、PDF 按需下載與離線重看。
- 合成 session 過期與 `auth.check` 失效後的單次重連、記憶體密碼、手動登入接續原任務，以及非讀取操作不重送。
- 累積審查表、薪資版本、監控、任務進度、取消及續跑。
- 審查同步首次逐案保存 `OrderName`、後續只補新案與失敗項目，空醫囑不重抓；本機醫囑名稱篩選、排序及離線檢閱。
- 手術排程兩個曆月、預設本人與指定其他醫師卡號、帳號隔離、ROC 日期、醫師尾碼、姓名與新增欄位、未定時間、原始狀態、失敗保留資料與離線重啟。
- Google 預覽差異、衝突、逾時核對、公式與人工欄位保留。
- 原始碼與凍結 EXE 使用同一組自我測試。
- EXE 內嵌的靜態檔、預設值、授權聲明與當次來源一致；發布前核對檔案雜湊。

報告在 `.build/ci/`；每次 GitHub Actions 執行亦附 `validation-<commit>` Artifact。EXE 自測與內容驗證報告也包含於 Release ZIP。具體測試數量以該次報告為準。

## 人工介面驗證

兩處手動輸入以空白、Enter、連續輸入和多行貼上檢查立即核對；進階工具另檢查停頓約 700 毫秒後自動核對及輸入法組字。選擇病人清單使用表格勾選或取消手動病人，進階工具仍可用病人 badge 移除，失敗項目可重試。檢查大清單的表格與進階工具 badge 可捲動瀏覽、鍵盤操作，以及已存集合編輯後仍保留原集合與掛號來源。任務送出時立即顯示等待進度；用無掛號來源的病人確認序號顯示「未提供」且最新 SOAP 可開啟。

使用 `tools/browser_bot_fixture.py --followup --library --local-board`，確認帳號切換、病人集合、工具設定、SOAP／tag、TAG 徽章定位、病人清單 176／156px 與小螢幕收合、靠左標題及病歷號複製、歷史資料對話框、切換系統後返回最近檢閱、搜尋、進度自動收起及刀房 iframe 載入／卸載。以合成資料檢查備註入口緊鄰 TAG、展開與自動儲存、重開後保留、帳號／任務隔離、序號缺值與歧義、批次列印預覽，以及生日當天、隔天生日與缺值顯示。檢查審查和薪資查詢列在桌面與窄螢幕可操作。確認該次／歷年掃描入口、醫囑與掃描 PDF／影像並排比較、跨功能保留、切換病人清空，以及鍵盤與窄螢幕單頁切換。比較模組與刀表另用合成 fixture 驗證，不連真實 Google 刀表。

## 院內驗收

1. 每個院區帳號登入及讀取權限；中文姓名、科別、醫師尾碼及身分證解析。
2. 預設「眼科」與「眼科、病例計酬」多關鍵字任一符合的科別名稱／代碼比對、最新／該次門診 SOAP、舊任務單字設定、空白補找、初診與權限失敗區分；特殊報告、左右眼與歷史涵蓋期間。
3. 新版門診清單的實際序號與前導零、舊快取更新，以及備註列印版面在臨床印表機的呈現。
4. 長時間連線、院方工作階段過期及每日監控實際更新。
5. 手術排程姓名／科別、日期範圍、本人與其他醫師卡號的院方授權及實際清單；即時刀房登入及 iframe 相容性。
6. 在刀表副本測試欄位對應、改期及 Google 寫入權限，確認後再使用正式刀表。
7. 實際院內掃描病歷的完整類別與日期、眼科紀錄和術前標示同意書區分、舊病歷號、選用的眼科就診連結核對與 PDF 下載；合成資料無法取代院內回應驗證。
8. 聯醫帳號的門診掛號紀錄在登入後與查過病人基本資料後皆可讀取；遇到真實病歷調閱審查時，核對只送出一次醫療用途原因且後續 SOAP 能繼續。若院方未提供該原因或未確認送出，應停止並在「爬蟲紀錄」檢查錯誤，不自動重送。

院內失敗時可從「爬蟲紀錄」開啟「DEBUG 資訊」。SDK 互動摘要與診斷跟著本機資料庫保存，詳細 SDK 日誌在帳號 `diagnostics/`；不要把真實病歷、身分證、帳密或完整診斷直接貼到公開 Issue。
