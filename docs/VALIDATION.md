# 驗證與院內驗收

公開測試全部使用合成病人、一次性測試金鑰與暫存資料庫，不含實測病歷或院內帳密。CI 與本機都執行 `tools/run_checks.py --build`。

## 自動驗證

- 來源發布範圍、版本標籤、SDK lock 一致性、公開登入預設值。
- Python 單元／整合測試、Ruff、JavaScript 語法及依賴檢查。
- 帳號隔離、SOAP 病人上下文、結構化 SOAP、tag 區塊、日期與快取。
- 累積審查表、薪資版本、監控、任務進度、取消及續跑。
- 手術排程兩個曆月、ROC 日期、醫師尾碼、原始狀態、失敗保留資料與離線重啟。
- Google 預覽差異、衝突、逾時核對、公式與人工欄位保留。
- 原始碼與凍結 EXE 使用同一組自我測試。
- EXE 內嵌的靜態檔、預設值、授權聲明與當次來源一致；發布前核對檔案雜湊。

報告在 `.build/ci/`；每次 GitHub Actions 執行亦附 `validation-<commit>` Artifact。EXE 自測與內容驗證報告也包含於 Release ZIP。具體測試數量以該次報告為準。

## 人工介面驗證

使用 `tools/browser_bot_fixture.py --followup --library --local-board`，確認帳號切換、病人集合、工具設定、SOAP／tag、抽屜、搜尋、進度自動收起及刀房 iframe 載入／卸載。比較模組與刀表另用合成 fixture 驗證，不連真實 Google 刀表。

## 院內驗收

1. 每個院區帳號登入及讀取權限；中文姓名、科別、醫師尾碼及身分證解析。
2. 同科最新 SOAP、空白補找、初診與權限失敗區分；特殊報告、左右眼與歷史涵蓋期間。
3. 長時間連線、院方工作階段過期及每日監控實際更新。
4. 手術排程姓名／科別／狀態欄位、日期範圍與實際院方清單；即時刀房登入及 iframe 相容性。
5. 在刀表副本測試欄位對應、改期及 Google 寫入權限，確認後再使用正式刀表。

院內失敗時可從任務開啟「查看診斷」。診斷跟著本機資料庫保存，詳細 SDK 日誌在帳號 `diagnostics/`；不要把真實病歷、身分證、帳密或完整診斷直接貼到公開 Issue。
