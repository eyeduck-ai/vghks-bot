# 病人轉送與刀表同步

## 狀態保存位置（6.9.0）

本版不增加隱藏分頁或同步欄位。月份／FU 保留既有兩個隱藏 ID 欄，年度封存沿用來源月份與列型態欄；日常臨床欄位與拖動／跨月整列剪貼的操作不變。

| 狀態 | 位置與原因 |
| --- | --- |
| 排程／既有事件識別 | 既有 `ScheduleSyncId`、`CalendarEventId` 隨整列移動，保持原事件與跨月身分 |
| 來源與寫入雜湊、人工位置基準、刪除／FU 綁定 | 唯一共享分頁 `__VGHKS_SYNC_STATE`，供不同電腦避免覆寫人工修改或重建已刪排程；沒有 SOAP 全文 |
| 預覽、執行歷史、已確認批次、離線意圖、完整備份 | 主程式帳號 SQLite；備份及操作明細壓縮保存，列表只查詢摘要 |
| 事件內容雜湊、未完成日曆操作、缺列次數、健康狀態 | 監控程式 SQLite；重啟後重新完成刪除確認 |
| 目前監控主機 | 單一固定 metadata，維持明確的主機接替規則 |

批次 metadata 只暫時保留。讀回核對完成後，先保存本機完成紀錄，再回收雲端標記；清理中斷後可續接。結果不明、無本機完成證據或其他資料庫的標記不自動刪除。本機完成紀錄即使雲端 marker 已回收，仍可禁止重送並核對後續人工異動。

請保留主程式與監控各自的完整資料目錄。更換電腦仍使用共享基準及整列 ID；本機歷史與尚待確認操作需透過資料庫備份攜帶，不能由刀表重建。重建監控目錄時須明確接替舊主機；6.9.0 的操作明細請使用 6.9.0 以上版本讀取。

## 從檢閱轉送

在病歷檢閱按目前病人的「送至進階工具」，或勾選左側病人後批次轉送。可只加入待處理，或加入並開啟工具。單一病人可指定來源 SOAP；批次採用該次檢閱保存的來源。每個帳號、每個工具有自己的累積清單；重複轉送同一病人合併成員，來源 SOAP 的新版本另行保存。移除或清空待處理清單不改動執行中任務的名單。

開啟白內障工具時，指定病人會聚焦並優先處理；單純加入不啟動讀取，也不解除原本的暫停。返回檢閱保留原任務、病人與畫面狀態。

刀表候選只使用所轉送來源。來源被更新或刪除後，請重新檢閱、轉送並產生預覽。符合既有追蹤 Tag 的來源會提供 FU 候選，可與手術同批預覽、套用；已綁定 FU 保留人工資料，不重複新增。沒有明確手術標記也能轉送；需要手動新增時按「新增手動刀表項目」，填妥日期、院區、眼別及術式，再預覽套用。改期須明確勾選「套用目的地／改期」，再按「讀取目的區塊」核對日期與院區；有重複區塊時選擇確切目的地。

## 主程式排程

刀表連線設定可從同一資料庫其他帳號帶入刀表目標與服務帳戶，不需登入來源帳號。複製後各帳號獨立保存設定，本帳號院區保持不變；也可繼續手動匯入 JSON。

手術候選、人工草稿及 FU 新增預設使用目前帳號的院區，可在預覽前選擇高榮或聯醫。院區只是新增預設，修改帳號院區不會搬動既有手術；既有排程仍按刀日標題與永久 ID 核對位置，人工改院區須明確勾選「套用目的地／改期」。舊帳號院區若不是高榮或聯醫，新增前須手動選擇，不自行猜測。

在更新刀表工具設定刀表與服務帳戶，啟用當日 SOAP 排程，預設每 60 分鐘執行。它只在主程式開啟且該帳號在線時生效；每輪重新讀取**本人當天門診清單及當次 SOAP**，不使用別人的門診或歷年快取代替。可立即執行、停用排程及開啟待核對候選。

自動手術來源須有明確結構化 A+P／Plan 標記及版本。取消、眼別／術式變更、多段無法追溯的來源、人工欄位衝突及不明配對停留待核對。一般欄位與改期分別判定；可信的新 SOAP 改期可自動處理，人工位置衝突只阻擋改期。

FU 使用目前帳號既有「追蹤」Tag 的判定規則，沒有另設解析語法。新增只填病歷號、姓名、帳號預設或手動選擇的醫院、Tag「FU」，其他可見欄位留白。手動預覽前只開放修改院區，病歷號、姓名與分類沿用來源。建立後永久綁定；人工修改醫院、Tag、補填欄位或刪除該列不會因同一來源再次出現而重建或覆寫。

## 不需病人名單的刀表管理

主程式「手術系統 → 線上刀表管理」可直接使用目前帳號的服務帳戶設定，不需先選病人或登入院內系統。院內連線與 Google 連線分別判定。既有手術更新已能自動建立缺少的月份及日期＋院區刀日；自動更新必須有可用月份範本，欄位不一致或區塊重複時停止並待核對。

管理頁可預覽建立指定月份、指定日期＋院區刀日；有月份範本時沿用完整表頭與格式，沒有月份時可建立標準空白月表。它不複製範本中的病人資料。已有相同月份或唯一相同日期＋院區時不重複建立。修復只處理能確定的系統識別欄、隱藏設定與表頭凍結，不猜補臨床欄位、不搬動病人或改報到時間；異常列與重複 ID 保留並列出問題。

每月手術統計可選起訖月份及院區，預設當月、全部院區；依所屬刀日分組，包含年度封存。OD／OS 計 1 眼、OU 計 2 眼，病歷號格顯示刪節線的取消列排除；側別不明保留明細並排除眼數。LenSx-Phaco-IOL 同時計入 LenSx 與 CATA；CATA、Cataract、Phaco-IOL、MSICS-IOL 計入 CATA。VT+MP 等組合拆項，同列相同術式只計一次；術式可重疊，總眼數獨立計算。

既有水晶體清單仍可按刀日日期範圍查詢。IOL 型號、Target 與 Final 分開顯示；型號統計同時列出排程列數與眼數／片數。型號只合併全半形、大小寫及多餘空白差異；多型號或雙眼分配不明列入待核對，不猜片數。報表只讀取，不回寫刀表；未取得月份與已取得的零筆月份分開顯示。

封存只接受已過去的月份。先將完整原生儲存格快照與操作紀錄保存在目前帳號本機資料庫，再複製至 `刀表封存_YYYY`；第 6 列為表頭，保留永久排程／事件 ID、人工欄位、格式與註記，並加上來源月份及列型態。核對成功後顯示「確認封存後移除原月份」，第二次操作才移除原月份。封存不可信、欄位無法安全對齊或來源被改動時停止；中斷時先按核對更新結果，不能重新建立同一批封存。封存的 ID 仍由日曆監控辨識，不因原月表移除而刪除事件。本機封存備份隨帳號資料庫備份一起保存，發布包不含這些資料。

複製完成但尚未移除來源的短暫階段，來源與封存同時含有相同 ID，主程式與監控會暫停相關同步；請核對並完成第二階段後恢復。水晶體統計也會列出重複識別問題，避免把暫存副本重複計數。來源／其他分頁的公式不能安全保留時，封存會停止並提示，保留原月份。

月份表頭的診斷摘要在封存表固定為封存時結果，原公式放入註記並完整保存在本機備份，避免搬到年度表後錯算全年範圍。封存保留列高及人工隱藏列，條件格式固定為封存當時的顯示樣式，原規則保存在本機備份。病人列僅允許純常數運算公式；函式、位址、陣列、命名範圍、範圍驗證或圖表無法安全保留時停止封存。可補封存較早月份，以原生插列保持月份順序、年度分頁 ID 與既有內容；既有相依公式、圖表或跨插入位置的合併範圍仍停止並要求核對。

配套 GAS 2026.10.15 的彙整入口同樣採預覽、私人整檔備份、複製核對、再次確認移除來源，使用 Sheets v4 保存原生格式與刪節線。主程式、GAS 與監控共用 `DOCUMENT` 可見的 `vghks.sheet.archive.lock`（固定 metadata ID 2147483646）；唯一 ID 的原子建立避免兩個封存入口同時開始。未完成交易保留標記，其他自動寫入暫停，查詢統計仍可使用；不依時間自動解除，回原入口核對。既有年度條件格式的固定轉換列於預覽並先備份，不調整人工保護設定。

新封存的月份區段註記包含 `VGHKS_ARCHIVE_CONTRACT_V2`。舊 GAS 封存可能已遺失取消狀態，不能由現有文字推回；相關月份統計標示不完整，須以私人備份核對。既有未完成的舊 GAS 交易不自動執行舊版刪除流程。

## Google 暫時無法使用

管理頁顯示最近成功讀取的時間；斷線時名單與統計可使用明確標示的本機快取，不能把快取當成最新刀表套用。未完成的建立／修復意圖保存在本機，連線恢復後重新產生預覽。套用前重新讀取並比對內容，寫後讀回核對；回應中斷時保留批次並只做核對，避免重複新增或誤刪。

Google 明確拒絕寫入（例如編輯權限不足）時，修正原因後可重新產生新預覽，不會永久封鎖管理功能。若封存副本已完成、移除原月份遭拒，仍保留兩份資料並要求核對原批次，再確認完成封存。

當日 SOAP 已成功取得但 Google 無法連線時，保存來源集合與待核對批次，排程結果標示部分完成。可在待確認項目按「重新連線並核對」；重試使用已保存來源重新規劃，不重送舊請求。來源版本或刀表設定已變更時要求重新確認。主程式重啟仍保留這些批次；沒有可用快取時明示尚未取得資料，不顯示成空白刀表或成功同步。

## 刀日及整列搬移

月份分頁名稱為 `YYYYMM`，第一列是實際欄名。刀日標題由「日期／報到時間＝日期、醫院＝院區、病歷號＝◆ 刀日」辨識；下方病人的有效日期與院區取自最近上方標題。病人自己的日期欄仍是報到時間。

同一天高榮與聯醫可各有區塊。新增須指定日期及院區，在該區塊空列不足時插列；同日期同院區的重複區塊需要人工選擇目的地。既有排程更新不因帳號預設院區改變而搬動。

請用左側列號選取**整列**後拖動，或整列剪下貼到另一月份，讓隱藏的 `ScheduleSyncId`、`CalendarEventId` 一起移動。每筆排程及刀日標題各有永久 ID；列號、月份及日期不是身分。初始化會對齊月份的隱藏欄位置；尾端空白欄數量可不同，實際欄位錯位須先核對。

人工搬移後，舊 SOAP 不會把排程搬回去；IOL／Target 更新保留報到時間、人工欄位、註記與原事件 ID。患者醫院欄可留白或手填，既有值及公式保留；程式不補填或依標題覆寫，院區判斷仍以刀日為準。重複 ID、病人綁定不符、孤立 ID、無有效刀日及欄位差異會保留資料並停止相關更新。

## 共享基準與協作

### 需要新增的欄位

不需新增臨床欄位。每個月份及 FU／All 只需兩個隱藏系統欄；已有欄位直接沿用，不另建同名欄。

| 欄位／分頁 | 用途 | 初始化方式 |
| --- | --- | --- |
| `CalendarEventId` | 保留並更新原日曆事件 | 已存在則沿用並隱藏，不自動建立保護 |
| `ScheduleSyncId` | 永久識別每筆排程及刀日區塊，隨整列搬移 | 缺少時自動補上並隱藏，不自動建立保護 |
| `__VGHKS_SYNC_STATE` | 多台主程式共用來源版本、欄位及位置基準 | 首次保存同步基準時自動建立的隱藏分頁 |

日期、院區、月份及列號會改變，病歷號也可能有雙眼、多次手術，不能單獨取代排程 ID。請用 EXE 的「檢查並準備刀表」執行初始化，避免自行在不同月份的不同位置插入系統欄；初始化會先檢查完整表頭，再對齊系統欄。若目前每月 A:W 是可見欄位及既有事件 ID，排程 ID 會補在 X；FU 原本 A:J 時補在 K。實際位置仍依讀取到的表頭決定。既有嚴格保護若不允許服務帳戶編輯技術欄，初始化會先列出 `protected_identity_range` 並停止，不移除或放寬原保護；須由擁有者將服務帳戶加入那些範圍的可編輯者。

每台電腦保留自己的本機資料。刀表隱藏分頁 `__VGHKS_SYNC_STATE` 共用來源識別、版本雜湊、欄位寫入基準與位置基準，不保存 SOAP 全文。

同步不依賴儲存格保護範圍；依使用者偏好，主程式、監控程式及 GAS 均只隱藏系統欄，不自動建立或重建保護。既有保護仍尊重其編輯權限，不由程式擅自移除。

雲端欄位仍等於上次系統寫入值時，才可自動接受新來源；人工修改保留，來源缺值不清空。原 SOAP、使用者預覽後的手動修正及最後成功寫入值分開保存，避免下輪撤回人工選擇。已刪除或封存的綁定不自動重建。

同機操作以刀表 ID 序列寫入。跨電腦每次重讀、重新定位、寫入前比對及讀回核對；偵測並行變動便停止該筆。Google Sheets API 不提供本方案所需的跨機條件式原子鎖，仍可能存在檢查後至寫入間的競爭時間。請錯開大量人工搬列與自動更新。

### 三者共用的解析規則

主程式與獨立監控使用 `vghks-sheet-core` 的同一解析實作；離線契約來自實際 GAS 測試匯出器，涵蓋純日期、刀日標記、院區、舊版表頭、診斷公式及報到時間。三者皆依第一列欄名定位，不把欄位字母當固定介面；`時間`、`日期/報到時間` 視為 `日期／報到時間`，FU 的 `日期` 保持獨立。診斷只識別正式欄名、`診斷｜…` 摘要或帶有既有摘要識別碼的公式。

有效刀日必須同時有 2000–2099 純日期、`◆ 刀日`、高榮或聯醫，且事件 ID 留白。日期可為原生整數日期序號或完整年月日文字，附英文三字母星期時必須正確；日期中的時間、民國年、錯誤星期及夾雜文字不得當成純日期。錯誤刀日或病人報到欄誤填完整日期會列待核對，不能繼承前一刀日。報到時間可用既有文字 HH:mm／HHmm 或原生時間值。

新月份沿用最新月份的完整表頭、公式、註記及格式，包含自訂欄和隱藏欄；既有月份真正欄位錯位時先停止建立或整列搬移，尾端空白網格欄數可以不同。GAS 負責既有格式整理，EXE 搬列使用完整原生儲存格內容，獨立監控只維護必要系統識別與事件綁定，不改寫患者院區。

離線核對：`python tools/verify_sheet_contract.py`；另外提供 GAS checkout 時使用 `--gas-repo <path>`，會重新執行實際 GAS 匯出器並比對保存的契約。完整建置流程也包含此檢查。

`tests/fixtures/gas_contract.json` 固定 GAS repository 與完整 commit；提供 checkout 時也核對 HEAD。CI 直接取此版本並執行 GAS 匯出器。更新 GAS 的欄位契約時，需一併審閱固定版本及兩份匯出樣本。

唯讀線上核對：`python tools/check_sheet_contract.py --service-account <本機金鑰路徑> --spreadsheet <刀表網址> --calendar-id <日曆ID> --report <本機報告路徑>`。此工具只讀取 API、在記憶體預演初始化；報告只包含欄位、權限、解析數量及診斷摘要，不輸出病人資料、事件內容或金鑰。Drive `canEdit` 和 Calendar `writer`／`owner` 是權限核對，仍不能代替實際寫入與儲存格保護範圍的驗收。

## 獨立日曆監控

日曆由 [vghks-sheet2cal](https://github.com/eyeduck-ai/vghks-sheet2cal) 的指定常駐主機負責，主程式只更新刀表。監控預設每 60 分鐘處理台北時間今天起的月份排程與 FU／All；以刀表目前日期與待核對改期狀態判斷，已確認完成且仍在過去的排程不查詢或變更日曆。刀表仍完整核對 ID，刀日與無日期 FU 不建事件，年度封存只保護既有事件。過去排程改到今天或未來後，恢復同步並更新原本綁定的日曆事件，保留 ScheduleSyncId 與 CalendarEventId，不需新增列。今天／未來改到過去時，更新原事件一次，回讀核對並保存完成狀態後略過；失敗或重啟續接原事件，不補建過去事件。缺列且已過去的事件仍保留。每份刀表僅登記一台主機，其他電腦或複製的資料庫不得同步。

整列改期保留同一事件；一般指定報到時間的手術為 30 分鐘，GA、未定時間及 FU 為全天，取消保留灰色事件。兩次完整成功掃描確認缺列才移除已確認擁有權的事件；錯誤、識別衝突、整頁消失及封存保留事件待核對。設定、備份、重啟與移機見獨立 repo。

## 共用規格與驗收

契約 1.2.2 的正式 JSON、合成案例及更新流程位於 [GAS repo](https://github.com/eyeduck-ai/op_spreadsheet/blob/master/docs/SHEET_CONTRACT.md)。主程式的 schema、identity、state 相容入口直接使用共用核心，與監控固定同一完整 Git commit；執行中不下載新規格。

測試涵蓋院區可留白、手填及公式保留、人工位置優先、跨月搬移、FU、離線來源、逾時核對、永久識別與原生封存。完整命令為 `python tools/run_checks.py --build`；日曆及主機服務回歸由獨立 repo 執行。
