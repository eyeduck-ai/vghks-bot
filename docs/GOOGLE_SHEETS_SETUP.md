# 刀表服務帳戶設定

1. 在 Google Cloud 選擇一個專案，啟用 **Google Sheets API**。建立服務帳戶，在「金鑰 → 新增金鑰 → 建立新的金鑰」下載 JSON。採 Google 官方服務帳戶授權：[說明](https://developers.google.com/identity/protocols/oauth2/service-account)、[建立金鑰](https://docs.cloud.google.com/iam/docs/keys-create-delete)。
2. 打開刀表的「共用」，將 JSON 中 client_email 對應的服務帳戶電子郵件加入為**編輯者**。不需提供網域全權委派或專案管理員角色。
3. 若系統欄已有嚴格保護，刀表擁有者還須在「資料 → 保護工作表和範圍 → 設定權限」中，將同一服務帳戶加入 `CalendarEventId`、`ScheduleSyncId` 既有保護範圍的可編輯者。共用整份刀表或另加警告式保護，都不會覆蓋原有嚴格保護；不需解除臨床欄位的保護。EXE 會先列出受阻範圍，停止整批初始化，不自行放寬原有權限。
4. 執行 VGHKS-bot，選定帳號工作區，從「手術系統 → 線上刀表管理 → 連線設定」匯入 JSON 金鑰及刀表網址，按「儲存並測試讀取」。不需要病人集合或院內登入，設定只屬於目前帳號，與該帳號的進階工具「刀表更新」共用。成功後顯示試算表名稱及月份分頁數；寫入仍需編輯者權限，且目標儲存格沒有額外保護限制。
5. 先用刀表測試副本產生管理操作預覽。可直接建立空月份或指定日期＋院區的刀日，核對後再套用並讀回確認。需要從 SOAP 更新病人時，再開啟進階工具「刀表更新」，核對刀日、眼別、術式、欄位與新增／搬移位置後套用。

JSON 金鑰只用於本機官方 google-auth 授權，與刀表設定一起以可攜式格式保存在目前資料庫、此帳號的 `clinical.sqlite3`。帶著 EXE 與完整 `VGHKS-bot-data` 換電腦即可使用，不需再次匯入。解密資料也在資料庫內，持有資料目錄的人能使用憑證；網頁不顯示私鑰。「移除本機金鑰」會解除資料庫內保存的金鑰，匯入前的原始 JSON 檔仍由您管理。

若顯示授權失敗，確認 Sheets API 已啟用、共用電子郵件與 client_email 一致、權限是編輯者，以及該區塊沒有另外限制服務帳戶編輯。組織若禁止建立服務帳戶金鑰，需由其管理者設定允許的授權方式。

Google 暫時無法連線時，刀表管理顯示快取時間並保存操作草稿，不能直接套用快取內容。恢復連線後重新讀取刀表並預覽；當日 SOAP 更新也會保留已取得的批次，重新連線時先核對來源版本。

寫入回應逾時或送達結果不明時，在管理操作或「刀表更新紀錄」按「核對更新結果」，沿用原批次核對。管理操作未確認前只可核對，不另建相同操作或盲目重送。Google 明確拒絕寫入時，修正權限或輸入後重新預覽；預覽後若刀表或 SOAP 有變動，也需重新確認。

手術開始時間供核對，主程式不以它覆寫報到時間。`ScheduleSyncId` 與 `CalendarEventId` 隨整列搬移保留；主程式只更新刀表，獨立 `VGHKS-calendar-monitor.exe` 負責日曆。

日曆監控另需啟用 **Google Calendar API**，並把指定日曆分享給服務帳戶，授予變更活動權限。在監控 EXE 的連線與排程頁匯入 JSON、刀表網址與 Calendar ID，按「檢查並準備刀表」後，再啟用每小時同步。主程式與監控分別保存憑證，監控不需要院內登入。完整設定及搬移規則見[刀表與日曆監控](SHEET_SYNC.md)。

現有 EXE 已包含官方 Google 授權與刀表寫入程式，完成以上設定即可使用，不必重新編譯、不必把 JSON 金鑰放入 EXE，也不需讓操作者在瀏覽器登入 Google。使用的院內電腦仍須能連線 Google OAuth／Sheets API；瀏覽器能打開刀表不代表服務帳戶已獲得分享權限。
