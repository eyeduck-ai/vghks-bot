# 刀表服務帳戶設定

1. 在 Google Cloud 選擇一個專案，啟用 **Google Sheets API**。建立服務帳戶，在「金鑰 → 新增金鑰 → 建立新的金鑰」下載 JSON。採 Google 官方服務帳戶授權：[說明](https://developers.google.com/identity/protocols/oauth2/service-account)、[建立金鑰](https://docs.cloud.google.com/iam/docs/keys-create-delete)。
2. 打開刀表的「共用」，將 JSON 中 client_email 對應的服務帳戶電子郵件加入為**編輯者**。不需提供網域全權委派或專案管理員角色。
3. 執行 VGHKS-bot，選擇院內帳號與病人集合，從「使用進階工具 → 刀表更新 → 刀表連線設定」匯入 JSON 金鑰及刀表網址，按「儲存並測試讀取」。設定只屬於目前帳號。成功後顯示試算表名稱及月份分頁數；寫入仍需編輯者權限，且目標儲存格沒有額外保護限制。
4. 先用刀表測試副本產生差異預覽。核對刀日、眼別、術式、欄位與新增／搬移位置後，按「套用更新」；完成後會讀回核對。

JSON 金鑰只用於本機官方 google-auth 授權，與刀表設定一起以可攜式格式保存在目前資料庫、此帳號的 `clinical.sqlite3`。帶著 EXE 與完整 `VGHKS-bot-data` 換電腦即可使用，不需再次匯入。解密資料也在資料庫內，持有資料目錄的人能使用憑證；網頁不顯示私鑰。「移除本機金鑰」會解除資料庫內保存的金鑰，匯入前的原始 JSON 檔仍由您管理。

若顯示授權失敗，確認 Sheets API 已啟用、共用電子郵件與 client_email 一致、權限是編輯者，以及該區塊沒有另外限制服務帳戶編輯。組織若禁止建立服務帳戶金鑰，需由其管理者設定允許的授權方式。

寫入回應逾時時，先在「刀表更新紀錄」按「核對更新結果」。未確認送達時可重試同一份預覽，請勿另建相同更新。預覽後若刀表或 SOAP 有變動，系統會要求重新預覽。

手術開始時間供核對，程式不以它覆寫報到時間。CalendarEventId 隨整列搬移保留；本版不呼叫 Google Calendar API。

現有 EXE 已包含官方 Google 授權與刀表寫入程式，完成以上設定即可使用，不必重新編譯、不必把 JSON 金鑰放入 EXE，也不需讓操作者在瀏覽器登入 Google。使用的院內電腦仍須能連線 Google OAuth／Sheets API；瀏覽器能打開刀表不代表服務帳戶已獲得分享權限。
